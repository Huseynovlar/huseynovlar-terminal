## 2. Logic Chain

1. **Why multiple subsystems appeared simultaneously "empty" or "fake" on the live VPS** → Tracing `backend/Dockerfile` (`WORKDIR /app`, `COPY config /app/config`) against `backend/app/core/config.py:37` (`parents[3] / "config"` = `/config`) proves YAML configs were unreadable in production, while `backend` lacked `panel_egress` internet access in `deploy/docker-compose.yml:65`. Fixing `CONFIG_DIR=/app/config`, adding `panel_egress` + DNS `[1.1.1.1, 9.9.9.9]` to `backend`, and replacing `hash(...)` in `treemap` + implementing the `economic_events` collector in `worker` makes Market Treemap, Verified Sources, World News, and Economic Calendar 100% live and real.
2. **Why authentication broke downloads, Incognito, Passkeys, and container buttons** → Tracing `auth/router.py:127` vs `deps.py:26` proves `ht_access_token` cookie was never issued; tracing `api-client.ts` proves expired 30-min access tokens were never refreshed via `/auth/refresh`; tracing `profile/route.tsx:224` & `auth/v2/login/route.tsx:67` proves WebAuthn options lacked `base64url <-> Uint8Array` conversion. Fixing dual cookie+Bearer auth (`SameSite=Lax`, `path="/"`), transparent 401 token refresh, Redis-backed WebAuthn challenges, and WebAuthn BufferSource helpers eliminates every auth failure across normal and Incognito sessions.
3. **Why the user demanded a complete multi-page Information Architecture (`"чтобы все было отдельно... страницы просмотра, добавление, редактирование, удаление были для всего, что можно"`)** → Inspecting `pages.config.ts:46-178` and `backend/app/modules/*/router.py` shows multiple sidebar links routed to the same URL (`/dashboard/crypto`, `/dashboard/analytics`), multiple unrelated domains crammed onto single pages (`/dashboard/profile`, `/dashboard/chat`, `/dashboard/default`), and missing `GET /{id}`, `PATCH /{id}`, `DELETE /{id}` endpoints on Accounts, Robots, Exness Profiles, Containers, Users, News Sources, and Wiki. Splitting every domain into its own clean route with dedicated List, Create, Detail View, Edit, and Delete pages/endpoints directly fulfills the user's architectural mandate.
4. **Why third-party keys belong in `/etc` without `chat_id` or `bot_token`** → Inspecting `server_telegram_bot/app/core/main.py:1122-1165` confirms `huseynovlar-core` already exposes `POST /internal/webhooks/trading` authenticated by `TRADING_WEBHOOK_SECRET` (`X-Trading-Webhook-Secret` / `X-Webhook-Secret`), which automatically fans out to subscribed Telegram users via `huseynovlar-alerts-bot` with `#trading` hashtags and retry/backoff. Therefore `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` are completely redundant; loading `GEMINI_API_KEY` + `TELEGRAM_WEBHOOK_URL` + `TELEGRAM_WEBHOOK_SECRET` from `/etc/huseynovlar-terminal/integrations.env` (and connecting `terminal-backend`/`terminal-worker` to `huseynovlar-core` over a shared internal Docker network) keeps secrets off the web UI while making alerts and Gemini work out-of-the-box.
5. **Why MT5 failed with `err=4014` and couldn't attach two EAs to one chart** → `image.png` + `image_2.png` + `ExnessPanelBridge.mq5` prove (a) MT5 WebRequest UI requires a dotted domain (solved by adding Docker network alias `ingest.terminal.local` on `exness_mt5_ingest` -> `http://ingest.terminal.local:8000` and/or `https://terminal.huseynovlar.org`), and (b) MT5 allows 1 EA per chart tab, so `ExnessPanelBridge.mq5` attaches to a **second chart tab** in the same MT5 terminal while `NasdaqPulse v3.01` stays untouched on Chart #1 (with optional `ExnessPanelHook.mqh` IPC now wired end-to-end in `ExnessPanelBridge.mq5`).
